==============================================================================
DATABASE - NEONDB (PRODUCTION)
==============================================================================

NeonDB is the managed serverless PostgreSQL provider used for production and
staging deployments (Render).

Two separate databases are required:
  coursedb  - used by lms.services.coursemanagement
  userdb    - used by lms.services.usermanagement

NeonDB connection string format (Npgsql key-value — use this everywhere):
  Host=ep-xxx.us-east-1.aws.neon.tech;Database=<dbname>;Username=neondb_owner;
  Password=<password>;SSL Mode=Require;Trust Server Certificate=true;

DO NOT use the URI format (postgresql://...) with Npgsql — use key-value only.

==============================================================================
DATABASE MIGRATIONS (NEONDB)
==============================================================================

Prerequisites:
  dotnet tool install --global dotnet-ef

Run from repo root:

  CourseDB:
  dotnet ef database update \
    --project src/lms.shared.data \
    --startup-project src/lms.services/lms.services.coursemanagement \
    --context CourseDbContext \
    --connection "Host=ep-xxx.us-east-1.aws.neon.tech;Database=coursedb;Username=neondb_owner;Password=xxx;SSL Mode=Require;Trust Server Certificate=true;"

  UserDB:
  dotnet ef database update \
    --project src/lms.shared.data \
    --startup-project src/lms.services/lms.services.usermanagement \
    --context UserDbContext \
    --connection "Host=ep-xxx.us-east-1.aws.neon.tech;Database=userdb;Username=neondb_owner;Password=xxx;SSL Mode=Require;Trust Server Certificate=true;"

Verify migrations applied (in NeonDB SQL Editor):
  SELECT * FROM "__EFMigrationsHistory";

==============================================================================
BUG FIXES APPLIED
==============================================================================

1. Proto case-sensitivity (Linux Docker build failure)
   File: src/lms.services/lms.services.discount.gRPC/Discount.gRPC/Discount.gRPC.csproj
   Change: Protos\discount.proto → Protos\Discount.proto
   Reason: Linux filesystem is case-sensitive; file on disk is Discount.proto

2. Swashbuckle + Microsoft.OpenApi version conflict (Swagger 500 error)
   Removed explicit Microsoft.OpenApi 3.5.1 pin from lms.buildingblocks.csproj
   Swashbuckle 10.1.7 requires Microsoft.OpenApi 2.4.1 (ABI incompatible with 3.5.1)

3. Aspire workload deprecation (NETSDK1228)
   Replaced IsAspireHost=true with <Sdk Name="Aspire.AppHost.Sdk" Version="13.2.2" />

4. CS0234 - Projects.* types not generated
   Added IsAspireProjectResource="true" on all ProjectReferences in AppHost

5. Runtime: Endpoint with name 'http' already exists
   Removed all WithHttpEndpoint() calls from AppHost Program.cs

6. Service discovery URL format
   Web app reads services__usermanagement__https__0 / services__usermanagement__http__0
   (Aspire-injected format), not MicroServices:UserManagementUrl

7. Npgsql version conflict on Render (get_LockReleaseBehavior error)
   Cause: Render build cache was loading Npgsql 8.0.4 despite lms.shared.data
          referencing 10.0.1. lms.services.aws was still on net8.0 causing
          the old version to be resolved transitively.
   Fix:   Bumped lms.services.aws and lms.shared.common to net10.0.
          Added explicit Npgsql.EntityFrameworkCore.PostgreSQL 10.0.1 reference
          to lms.services.coursemanagement.csproj.
          Added global.json to lock SDK to 10.0.201.
          Clear build cache on Render before redeploying.

8. Unable to retrieve project metadata (dotnet ef error)
   Cause: lms.shared.data and lms.shared.common targeted net8.0 while startup
          projects target net10.0 — framework mismatch.
   Fix:   Updated both to net10.0 with matching package versions.
